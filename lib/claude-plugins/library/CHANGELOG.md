## [1.0.0] - 2026-10-30

### feat(lib-0049): release-pr as the library plugin, marketplace under lib/

The `release-pr` skill is now a versioned plugin, and the `library` marketplace now lives under `lib/` (LIB-0049 §4, as its new amendment builds it).

**What a consumer changes:** nothing yet.

- **pigeon-cli's pin keeps loading.** It pins `claude-plugins/pigeon-cli/v1.0.1`, whose tree still has the root marketplace. Every plugin tag from now on names a release commit that copies `lib/claude-plugins/marketplace.json` to `/.claude-plugin/marketplace.json`, so a `github` marketplace pinned at the tag loads exactly as before.
- **runway takes the new plugin in a separate PR.** That PR pins `claude-plugins/library/vX.Y.Z` in `.claude/settings.json` and drops `.claude/skills/`.

**What's new:**

- **`library` plugin.** `lib/claude-plugins/library/` holds `release-pr`, copied unchanged from `.claude/skills/release-pr/`. This PR cuts its first version.
- **The marketplace moves.** It is now `lib/claude-plugins/marketplace.json`, and lists `library` beside `pigeon-cli`.
- **garden plugin pages.** `generate-module-redirects.sh` writes one page per loadable plugin version at `noisypigeon.garden/claude-plugins/<plugin>/vX.Y.Z/`, with the `.claude/settings.json` that pins it. A tag counts as loadable only if its commit's marketplace names the plugin at a source its tree holds. garden gets the templates and the section marker.
- **Release automation.** `template-release.yml` builds both kinds of tag-only release commit with one `release_commit` helper. That covers `workflows/` and now `claude-plugins/`. A collision with a path already on `main` fails the step before anything is tagged.
- **LIB-0049 records this.** It gains an `## Amendments` entry: the marketplace takes §4's tag-only fallback rather than a URL, steps 2a and 2b were one PR, and LIB-0048's expected version numbers were taken.
